# AI Review Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add separately presented compliance and marketing AI opinions to saved revisions without changing human approval semantics or queue performance.

**Architecture:** Root implements shared contracts and the provider adapter. Backend and frontend work in parallel against those contracts; root integrates and verifies. PostgreSQL stores completed reviews and atomic request quotas. No new cache service or asynchronous job infrastructure.

**Tech Stack:** Deno/Fastify, native fetch to OpenAI Responses API, Zod, Postgres/PGlite, Next.js/React.

**Spec:** `docs/superpowers/specs/2026-11-03-ai-review-design.md`

## Global Constraints

- Saved current revisions generate on demand; existing historical results remain readable.
- Default model `gpt-5.4-mini-2026-03-17`; provider timeout 40 seconds; no automatic retries; `store: false`.
- One successful review per case/revision; 50 global attempts/day by default, 10 per workspace/day; UTC dates.
- AI is advisory. It never changes case status, approval, deterministic analysis, or existing dispositions.
- No provider calls or AI-result joins in the queue or ordinary case-detail endpoint.

## Review Focus

- A new revision during a slow model call must produce a conflict rather than a misleading result on the new revision.
- Concurrent requests on several app instances must respect the daily database-backed request cap.
- Text that asks the AI to ignore instructions must stay inside the untrusted data payload.
- Model quotations and reference identifiers must exist in the supplied context before saving.
- Changing selected revision while a request is in flight must not show that response on a different revision.
