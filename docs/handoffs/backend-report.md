# Backend implementation report

The API exports `createApiServer({ store, analyze, offers, policyVersion, cookieSecret, production?, seed?, allowedOrigins? })` from `apps/api/src/server.ts`. It returns a Fastify instance suitable for `inject()`; set `seed: false` for isolated route tests. `packages/models/mod.ts` exports `createTestStore()` for isolated in-memory PGlite and `createStore({ databaseUrl?, dataDir?, migrate? })` for Postgres or persistent PGlite. Store mutations return explicit `Result` values, serialize with `SELECT ... FOR UPDATE`, and commit the revision, decision and audit changes in the same transaction. The numbered SQL schema lives in `packages/models/migrations/001_initial.sql`; `deno task migrate` applies it. Startup migrates local storage only. Production requires a database URL, WEB_ORIGIN, and a cookie secret of at least 32 characters; apply migrations explicitly before starting it.

A signed HttpOnly SameSite=Lax cookie with a seven-day lifetime identifies a separate seeded workspace per visitor. The `x-demo-role` header simulates a reviewer or submitter and is not authentication or authorization. Production must place real authentication and authorization in front of any non-demo use. `WEB_ORIGIN` sets the required production browser origin allowlist as comma-separated exact origins when cross-origin requests reach the API directly; the intended Next proxy is same-origin. No submitted URLs are fetched.

Verification: `npm test` passed all 85 tests with the project’s restricted Deno task permissions, including the real-analyzer seed integration and a maximum-length Unicode submission. Persistence tests use a temporary directory under `.data/test-tmp`. The API request body limit is 192 KiB to accommodate valid encoded input.

Hosted Postgres verification: JSONB parameters are explicitly cast through text to avoid postgres.js double-encoding already-serialized values. A Neon probe verified creation, revision, and a freshly seeded six-case workspace. Seed failures return an error without issuing a cookie; existing empty demo workspaces receive a new seeded workspace on the next queue request. Concurrent empty-workspace recoveries may create separate seeded workspaces, with the browser retaining the last cookie. Seed cases run sequentially; an attempted parallel initialization was reverted after a hosted 500. The cause of that failure remains unconfirmed.
