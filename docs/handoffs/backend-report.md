# Backend implementation report

The API exports `createApiServer({ store, analyze, offers, policyVersion, cookieSecret, production?, seed?, allowedOrigins? })` from `apps/api/src/server.ts`. It returns a Fastify instance suitable for `inject()`; set `seed: false` for isolated route tests. `packages/models/mod.ts` exports `createTestStore()` for isolated in-memory PGlite and `createStore({ databaseUrl?, dataDir?, migrate? })` for Postgres or persistent PGlite. Store mutations return explicit `Result` values, serialize with `SELECT ... FOR UPDATE`, and commit the revision, decision and audit changes in the same transaction. The numbered SQL schema lives in `packages/models/migrations/001_initial.sql`; `deno task migrate` applies it. Startup migrates local storage only. Production requires a database URL, WEB_ORIGIN, and a cookie secret of at least 32 characters; apply migrations explicitly before starting it.

A signed HttpOnly SameSite=Lax cookie with a seven-day lifetime identifies a separate seeded workspace per visitor. The `x-demo-role` header simulates a reviewer or submitter and is not authentication or authorization. Production must place real authentication and authorization in front of any non-demo use. `WEB_ORIGIN` sets the required production browser origin allowlist as comma-separated exact origins when cross-origin requests reach the API directly; the intended Next proxy is same-origin. No submitted URLs are fetched.

Verification: `npm test` passed all 116 tests with the project’s restricted Deno task permissions, including real-analyzer seeds, a maximum-length Unicode submission, summary-query counts, atomic initialization/rollback, chronological seed ordering, and the optional AI API/storage/provider boundaries. Both Deno and frontend type checks passed. Persistence tests use a temporary directory under `.data/test-tmp`. The API request body limit is 192 KiB to accommodate valid encoded input.

AI increment: server dependencies additionally accept `aiReviewer` and `aiReviewDailyLimit`. GET `/api/cases/:id/ai-review?revision=N` reads a saved opinion and reports provider availability. POST with `{expectedRevision}` generates for the current saved revision, with scoped access, safe errors, cache reuse, and in-process coalescing. `getAiReview`, `saveAiReview`, and `consumeAiReviewBudget` keep results scoped to the workspace, serialize save against edits, and reserve UTC quotas atomically. Migration 002 is additive. Two instances can both call the provider, but both consume quota and return the single persisted winner. Real Neon verification admitted exactly two of five concurrent reservations with a workspace cap of two, confirmed JSONB objects, and preserved approval/revision behavior. No AI joins or provider calls were added to queue/detail reads.

Hosted Postgres verification: JSONB parameters are explicitly cast through text to avoid postgres.js double-encoding already-serialized values. Neon probes verified creation, revision, and freshly seeded six-case workspaces. Seed failures return an error without issuing a cookie; existing empty demo workspaces receive a new seeded workspace on the next queue request. Concurrent empty-workspace recoveries may create separate seeded workspaces, with the browser retaining the last cookie.

Performance follow-up: `listCases` uses one scoped SQL query for current-revision summaries, reused by the API during empty-workspace detection. `createSeededWorkspace` validates review decisions and atomically inserts the complete seed set with at most six statements. Explicit seed timestamps preserve case, disposition, and event order. The workspace/order index was applied on Neon. Revision `67j4axdcs13z` passed the full hosted smoke and a three-visitor concurrency probe. This replaces the earlier sequential seed fallback; no Redis cache was introduced.
